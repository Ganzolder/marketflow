# Подробная инструкция: ограничение Firebase API ключа

Ограничение нужно, чтобы ваш API ключ работал только с вашим сайтом и не мог быть использован с других доменов (даже если кто-то узнает ключ из кода или сети).

---

## Шаг 1. Войти в Google Cloud Console

1. Откройте в браузере: **https://console.cloud.google.com/**
2. Войдите в тот же Google-аккаунт, с которым создан проект Firebase **marketflow-ppnsi**.
3. В верхней панели (рядом с логотипом Google Cloud) выберите проект:
   - Нажмите на выпадающий список с названием проекта.
   - Найдите и выберите **marketflow-ppnsi** (или тот, что привязан к вашему Firebase).

Если проекта нет в списке — откройте Firebase Console → Project settings и проверьте, какой Google Cloud project ID у приложения.

---

## Шаг 2. Открыть раздел «Учётные данные» (Credentials)

1. В левом меню нажмите **«Навигационное меню»** (три горизонтальные полоски вверху слева), если меню свёрнуто.
2. Выберите **APIs & Services** → **Credentials**  
   (или откройте напрямую: https://console.cloud.google.com/apis/credentials )
3. Откроется страница со списком ключей и сервисных аккаунтов.

---

## Шаг 3. Найти нужный API ключ

1. В блоке **«API Keys»** (API-ключи) отображаются ключи типа **Browser key** / **Web key**.
2. Найдите ключ, который используется в приложении:
   - В коде у вас был ключ вида `AIzaSy...` — в списке будет строка с именем ключа и датой создания.
   - Имя может быть, например, «Browser key» или «Web client» или то, что вы задали при создании приложения в Firebase.
3. Нажмите **на название ключа** (не на сам ключ), чтобы открыть настройки этого ключа.

Если ключей несколько — нужен тот, который совпадает с `apiKey` в конфиге Firebase (Firebase Console → Project settings → Your apps → Web app → config).

---

## Шаг 4. Ограничить ключ по сайтам (HTTP referrers)

На странице редактирования ключа:

1. **Application restrictions** (Ограничения приложения):
   - Выберите переключатель **«HTTP referrers (web sites)»**  
     (в интерфейсе на русском может быть: **«HTTP-источники (веб-сайты)»**).
   - В блоке **«Website restrictions»** нажмите **«ADD AN ITEM»** / **«Добавить элемент»**.

2. Добавьте по одному элементу для каждого допустимого источника (без лишних пробелов):

   | Что вводить | Когда использовать |
   |-------------|--------------------|
   | `http://localhost:*` | Разработка на своём компьютере |
   | `http://localhost:9002/*` | Если приложение крутится только на порту 9002 |
   | `https://ваш-домен.com/*` | Ваш продовый домен (замените на реальный) |
   | `https://*.ваш-домен.com/*` | Все поддомены (например, www.ваш-домен.com) |
   | `https://*.vercel.app/*` | Деплой на Vercel (все превью и прод) |
   | `https://ваш-проект.vercel.app/*` | Только один конкретный домен Vercel |
   | `https://*.web.app/*` | Деплой на Firebase Hosting |
   | `https://*.firebaseapp.com/*` | Домен приложения Firebase |

   Примеры готовых строк (скопируйте и подставьте свой домен):
   ```
   http://localhost:*
   https://*.vercel.app/*
   https://marketflow-ppnsi.web.app/*
   https://marketflow-ppnsi.firebaseapp.com/*
   ```

   Важно:
   - В конце домена используйте `/*` (все пути на этом сайте).
   - Для localhost — `http://localhost:*` (все порты) или `http://localhost:9002/*`.
   - Звёздочка `*` только в допустимых местах (поддомен или путь).

3. Не добавляйте лишние сайты. Только те, с которых реально открываете приложение.

---

## Шаг 5. (По желанию) Ограничить список API

Ниже на той же странице:

1. **API restrictions** (Ограничения API):
   - Выберите **「Restrict key」** / **「Ограничить ключ」**.
   - В списке отметьте только те API, которые нужны приложению, например:
     - **Firebase Installations API**
     - **Firestore API** (если используете БД)
     - **Cloud Storage for Firebase** (если используете Storage)
   - Остальные снимите, чтобы ключ не работал с другими сервисами Google.

Если не уверены — этот шаг можно пропустить; ограничение по HTTP referrers уже сильно снижает риск.

---

## Шаг 6. Сохранить изменения

1. Внизу страницы нажмите **「SAVE」** / **「Сохранить」**.
2. Подождите несколько секунд — изменения применятся.

После этого ключ будет принимать запросы только с указанных сайтов. Запросы с других доменов Google будет отклонять.

---

## Проверка

1. Откройте ваше приложение с **разрешённого** домена (например `http://localhost:9002` или ваш продовый URL).
2. Убедитесь, что данные из Firebase загружаются (страницы, кампании и т.п.).
3. Если что-то перестало работать — проверьте, что домен добавлен в **HTTP referrers** без опечаток и с правильным `/*` или `*` в конце.

---

## Частые ошибки

- **Добавлен только `https://сайт.com` без `/*`** — нужно `https://сайт.com/*`.
- **Опечатка в домене** (например `vercel.app` вместо `vercel.app`) — ключ не будет работать с этого домена.
- **Забыли добавить localhost** — приложение не заработает при локальной разработке.
- **После изменений не сохранили** — нажмите **SAVE** внизу страницы.

Если нужно добавить новый домен (например, новый продовый URL) — снова откройте этот ключ в Credentials и добавьте ещё один элемент в **Website restrictions**, затем сохраните.
