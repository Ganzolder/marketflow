# Безопасность MarketFlow

## 1. Переменные окружения (обязательно)

- **Локально:** в корне проекта создайте `.env` (он в .gitignore) и заполните по образцу `.env.example`. Никогда не коммитьте `.env`.
- **На хостинге** (Firebase App Hosting / Vercel): в настройках проекта добавьте те же переменные. Пароли и секреты задавайте только там, не в коде.

Убедитесь, что заданы:
- `NEXT_PUBLIC_FIREBASE_API_KEY` — ключ из Firebase Console (иначе приложение не подключится к БД).
- `ADMIN_USERNAME`, `ADMIN_PASSWORD` — свой логин и **сложный** пароль в проде.
- `SESSION_SECRET` — случайная строка **не короче 32 символов** (например: `openssl rand -base64 32`).
- `GEMINI_API_KEY` — если используете AI-функции.

---

## 2. Ограничить Firebase API ключ (важно)

Ключ из конфига Firebase попадает в браузер — так устроена клиентская инициализация. Его можно обезопасить только ограничениями в Google Cloud:

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) → выберите проект **marketflow-ppnsi**.
2. **APIs & Services** → **Credentials** → найдите ключ типа «Browser key» / API key (тот, что в конфиге Firebase).
3. Нажмите на ключ → **Application restrictions**:
   - Выберите **HTTP referrers**.
   - Добавьте только свои домены, например:
     - `https://ваш-домен.com/*`
     - `https://*.vercel.app/*` (если деплой на Vercel)
     - `http://localhost:*` (для разработки)
4. **API restrictions** (по желанию): ограничьте ключ только нужными API (например, Firestore, Storage).
5. Сохраните.

Так ключ не смогут использовать с чужих сайтов.

---

## 3. Сменить ключ Firebase (если он уже светился в репо)

Если старый API key был в публичном репозитории:

1. В [Firebase Console](https://console.firebase.google.com) → **Project settings** → **Your apps** → веб-приложение.
2. В разделе с ключами создайте **новый** Web API key (или в [Google Cloud Console](https://console.cloud.google.com/apis/credentials) создайте новый ключ и привяжите к проекту Firebase).
3. Ограничьте новый ключ по шагу 2 выше.
4. В `.env` и в настройках хостинга замените значение `NEXT_PUBLIC_FIREBASE_API_KEY` на новый ключ.
5. Передеплойте приложение.
6. В Google Cloud Console **удалите или отключите** старый ключ.

---

## 4. Пароль и сессия в проде

- В продакшене задайте **свой** пароль админа (не из примеров).
- `SESSION_SECRET` в проде должен быть **уникальным** и длинным (≥32 символа). Сгенерировать: `openssl rand -base64 32` или аналог.

---

## 5. Регулярно

- Не коммитить `.env` и любые файлы с паролями или ключами.
- Проверять, что в репозитории нет реальных ключей: `git log -p -- .env` не должен показывать добавление .env с секретами (если когда-то коммитили — сменить все такие секреты).
- Обновлять зависимости: `npm audit` и обновления по безопасности.
